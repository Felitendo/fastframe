fastframe 0.10.1 fixes a crash in 0.10.0 on Linux: an app playing to ALSA's "Discard all samples" device was killed by the kernel within about a second. Upgrade from 0.10.0 straight away.

Upgrade by moving every fastframe crate to the tag:

```toml
fastframe-audio = { git = "https://github.com/crmne/fastframe", tag = "v0.10.1" }
```

No change is required.

## Fixed

- **Apps no longer get killed when playing to a device that never waits (`fastframe-audio`, Linux).** 0.10.0 made the output's callback thread real-time on every device. ALSA's `null` PCM, "Discard all samples" in cpal's device list, is always ready, so its callback never waits. A real-time thread that never waits uses up `RLIMIT_RTTIME` (200 ms) and the kernel kills the whole process, where before 0.10.0 it only kept one core busy. The output now makes the thread real-time only on devices that wait for the hardware, by cpal's own rule (`is_rt_eligible`): cpal's PipeWire and PulseAudio hosts, and ALSA's `hw` devices. ALSA's `null`, `default`, `pulse`, `pipewire`, `plughw` and `dmix` devices, and other plugins, keep ordinary priority, since they can spin or wait on a sound server. As a second line of defence, every callback measures how much of each 40 ms its thread ran; a thread that ran for most of it takes back any raised priority itself, which needs no privilege, long before the limit, and logs once. No signal handler is installed. Checked on real devices: on ALSA's `null` device the thread now keeps ordinary priority and plays to the end, where 0.10.0 was killed; a USB audio interface's `hw` device still gets real-time priority through RTKit; without RTKit both keep ordinary priority without failing. Reported and verified by the Spotifast session. By @crmne.

## Known limitations

- **ALSA devices other than `hw` stay at ordinary priority.** cpal keeps a stream's PCM type to itself, so the rule goes by the device's name. Apps on cpal's native PipeWire or PulseAudio host keep the real-time callback; an app on ALSA's `default`, `pipewire` or `pulse` device, which goes through the sound server's plugin, does not. To keep the real-time callback on a normal Linux desktop, enable `fastframe-audio`'s `pipewire` or `pulseaudio` feature (or both, as Solco does), so cpal's default host is the sound server rather than ALSA. Without either feature, every device an app lists is an ALSA one.
