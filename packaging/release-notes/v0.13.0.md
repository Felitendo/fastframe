fastframe 0.13.0 lets apps use local interface fonts, follow the desktop's text size, start sleep work immediately, and serve signed updates from their own HTTPS feed. It also fills regional Han font gaps and removes output scratch-buffer allocation from the first audio callback and larger later callbacks.

Upgrade every fastframe crate to the same tag:

```toml
fastframe-fonts = { git = "https://github.com/crmne/fastframe", tag = "v0.13.0" }
```

**Apps using the egui fork must update their patch pins.** fastframe now requires egui/eframe 0.36.2. The maintained `crmne/egui` branch `apps-0.36.2` is at `6ce633ba5f7f64d19ef6d204f9377da560bb546b`; winit stays at `ed7caa9023f10b397f5b6ec8284a840cbd8a6f65`. Update every patched egui crate together using the [complete patch block](https://fastframe.dev/getting-started/#egui-and-winit-forks). An app pinned to `=0.36.1` also changes that requirement. Apps on published 0.36.2 need no patch changes. No existing fastframe function or struct needs a code change.

## New

- **Use a local font without rebuilding the font setup (`LocalFont`, `FontSetup::local_font`).** Validated TrueType and OpenType faces, including an explicitly selected collection face, lead the interface families. Variable fonts follow the existing weight roles; static fonts share one face without synthesizing bold. System or Inter fonts and script fallbacks stay behind it, with fallback baselines aligned to the local font. Monospace stays unchanged. Reads are bounded to 32 MiB, and loaded fonts keep immutable bytes instead of rereading a file. The app owns its picker, settings, copying, and cleanup. By @crmne, extracted from @mauriciobc's [ZapFast font setting](https://github.com/crmne/zapfast/pull/335); thanks @eternalwaitt for [#26](https://github.com/crmne/fastframe/issues/26).
- **Follow the desktop's text size (`text_scale`, `watch::watch_text_scale`).** Linux Wayland apps can read GNOME's text-scaling factor and follow changes through the desktop portal. Apps decide how to combine it with their own zoom. The watcher reconciles changes made before subscription, and old portal calls are tried only when `ReadOne` is unavailable, without doubling timeouts on other errors. By @pch, with integration fixes by @crmne, in [#30](https://github.com/crmne/fastframe/pull/30).
- **Start urgent work before the UI handles sleep (`Power::on_suspending`).** The reader runs a short app hook before queuing the sleep event, without holding the hook mutex, and contains unwinding panics. `take_suspended_at` returns the recorded wall-clock time once, and `Ack::is_done` lets app tests check acknowledgement. By @dennisgr7 in [#24](https://github.com/crmne/fastframe/pull/24).
- **Serve signed updates from an app's own HTTPS feed (`Source::feed`).** Private-repository apps can publish release metadata and downloads on their own origin without shipping a GitHub token. A publisher key is required, and downloads and redirects stay on that origin. Stable and prerelease clients can share a feed: prerelease downloads read the selected version's assets from `releases.json`, rather than assuming `latest.json` describes it. Existing local feeds get the same correction. By @Halvanhelv, with release-selection fixes by @crmne, in [#3](https://github.com/crmne/fastframe/pull/3).

## Fixed

- **Regional Han characters have complementary fallback faces.** macOS keeps a broad Han face ahead of short Korean hanja faces, then adds up to three more cascade faces that fill simplified Chinese, traditional Chinese, or Japanese gaps. Each gets a separate key and baseline adjustment; faces without rasterizable outlines are skipped. Linux and Windows only add the simplified-Chinese fallback when the registered face lacks its probe. By @shiroamada and @crmne in [#27](https://github.com/crmne/fastframe/pull/27); thanks @hewigovens and @kongchu2 for [#18](https://github.com/crmne/fastframe/issues/18).
- **The first output callback and larger driver periods no longer grow a scratch buffer.** Conversion storage is allocated and initialized at open, and larger callbacks render in bounded, frame-aligned chunks. Renderer block limits still apply; clock and idle accounting stay per device callback. Allocation-counting regression tests exercise first and growing callbacks. This completes the output fix begun in 0.12.1. By @crmne; thanks @rojnwa for [#21](https://github.com/crmne/fastframe/issues/21).
- **App fork pins now include egui 0.36.2.** The app patches were rebased onto 0.36.2, and the redraw fix already included upstream was removed from the patch stack. Apps no longer need to step back to 0.36.1 to use the documented patches. By @crmne; thanks @pch for [#29](https://github.com/crmne/fastframe/issues/29).
- **The project is easier to explore.** The README now leads with the logo, a short setup example, native light/dark screenshots, a concise crate table, and the Sponsor link. The docs retain the theme's standard Sponsor button. Copilot instructions match the account policy. By @crmne.

## Known limitations

- macOS still has no native sleep reader in `fastframe-power`; injected sleep events work there. The new hook is called by native readers on Linux and Windows. Wall-clock sleep duration can be affected by clock adjustments.
- Desktop text scaling is followed through the GNOME portal on Wayland. X11 and other platforms return 1. Apps that force X11 inside a Wayland session must not apply the portal scale too.
- Local fonts need rasterizable Latin outlines. Bitmap-only and colour-only fonts are refused. A variable font may use up to four copies of its file in egui. The font picker and settings integration remain changes for each app.
- The macOS Han selection policy has platform-independent regression tests and cross-compilation checks, but the expanded cascade has not been visually tested on a Mac in this release session.
- The output allocation guarantee covers fastframe's conversion and rendering loop, not allocations inside the app's renderer or audio backend. Input conversion buffers may still grow when their driver period grows.
- The Linux audio requirements and PipeWire default-input startup delay documented in [0.12.1](https://github.com/crmne/fastframe/releases/tag/v0.12.1) still apply.
