fastframe 0.14.1 keeps the previous run's log. An app that hung and was killed used to lose its log to the restart that followed, which is when someone goes to attach it to a bug report.

Upgrade by moving every fastframe crate to the tag. Nothing changes in an app's code:

```toml
fastframe-log = { git = "https://github.com/crmne/fastframe", tag = "v0.14.1" }
```

## New

- **The earlier run's log is kept beside the new one (`Logging::file`, `previous_log`).** Before opening a fresh log, `Logging::file` moves the earlier run's file to `<name>.previous.<extension>`, so `zapfast.log` becomes `zapfast.previous.log`, replacing an older one there. `previous_log(path)` names that file, for an app that shows or opens it. A rename that fails is ignored and the new log is made anyway. By @crmne, after a frozen window in [crmne/zapfast#560](https://github.com/crmne/zapfast/issues/560) whose log the restart had replaced; thanks @Isllanrx.
