fastframe 0.5.0 gathers what the apps built since 0.4.1. There are four new crates:
- `fastframe-power`: the device's power, session and network state.
- `fastframe-file`: saves that are never half written.
- `fastframe-desktop`: the app's desktop entry, GNOME, and desktop settings without `gsettings`.
- `fastframe-shell` now remembers each window's size, position and maximized state.

The shell sleeps in the tray until something is due, and an audio output that silently stops playing reopens itself. The fallback fonts take a fraction of the memory.

Upgrade by moving the tag on every fastframe crate:

```toml
fastframe-shell = { git = "https://github.com/crmne/fastframe", tag = "v0.5.0" }
```

Three changes may be needed when moving the tag:

- **Handle `fastframe_audio::Reason::Stalled`** if the app matches on the reason of `Maintained::Reopened`.
- **Handle `fastframe_shell::Headless::WaitFor`** if the app matches on `Headless` rather than only returning it.
- **`fastframe_fonts::Fallback::bytes` is now `&'static [u8]`.** Code that borrowed it with `&fallback.bytes` still compiles. Code that needs an owned copy calls `.to_vec()`.

## New

- **Power, session and network state (`fastframe-power`).**
  - **Conditions:** energy saver, battery, display off, a locked session, the network's reach and whether it is metered.
  - **Events:** about to sleep, woke up, the session is ending. Sleeping and ending wait briefly for the app to save first.
  - **In the background:** EcoQoS on Windows, and `Activity` keeps audio playing behind another app out of App Nap on macOS.

  The app reads it all in its logic pass, with or without a window, and decides what to do: draw less, poll less, hold a download, reconnect after a wake. It is Spotifast's power module. That covers the readers by @dennisgr7 (spotifast#728, metered networks from spotifast#735), macOS network reach by @saikumargudelly (spotifast#795), and App Nap by @ECuteri (spotifast#789). By @crmne.
- **Windows open where they were left (`fastframe_shell::window::Geometry`).** The app keeps the size, position and maximized state in its own settings and applies them before the window exists, so it opens in place instead of jumping there. Sizes are in logical pixels, so a window saved while the interface was zoomed opens at the same size. A minimized or full-screen window is not remembered, and corrupt values are ignored. On macOS, a position whose title bar would be on no connected screen is dropped. `recover_offscreen` now also brings back a macOS window restored there. From ZapFast's window memory by @jbouhier (zapfast#385) and Spotifast's screen check by @HEOJUNFO (spotifast#774). By @crmne.
- **On niri, the existing window comes forward.** Wayland drops an app's request to focus its own window. `raise_on_compositor()` asks niri instead, which switches to the window's workspace rather than opening a new window on the current one. By @tassiovirginio (zapfast#474) and @crmne.
- **Saves that are never half written (`fastframe-file`).** `write`, `write_private` and `write_with` write a temporary file beside the target and flush it to the disk. They then move it over the target in one step, with write-through on Windows and a directory sync on Unix. A failed step leaves the old file as it was. It takes the most careful of Spotifast's, Solco's and ZapFast's save routines. By @crmne.
- **The app's desktop identity (`fastframe-desktop`).**
  - `desktop_entry(own)` gives the Flatpak-aware desktop entry name. Media controls, notifications and the window's app id must agree on it.
  - `is_gnome()` tells whether the session is GNOME.
  - `setting(namespace, key)` reads a desktop setting, such as GNOME's clock format or button layout, through the desktop portal. That works inside a Flatpak and starts no `gsettings` process.

  `fastframe-now-playing` re-exports `desktop_entry` from here. By @crmne; the GNOME check by @claudiocp (zapfast#467).
- **In the tray, the app sleeps until something is due.** Without a window the shell ticked every 150 ms. It now sleeps until the `Waker` wakes it, or until the time the app gives with `Headless::WaitFor`. Paused in Spotifast's tray, its wake-ups fell from 117 to 6 a second. By @dennisgr7. (#20)
- **On Windows, the audio thread keeps audio priority.** The stream's thread joins MMCSS as an "Audio" task, which keeps it ahead of background work and out of power throttling. In Spotifast with EcoQoS on, its priority went from 9 to 21. By @dennisgr7. (#19)

## Fixed

- **An audio output that stops playing without an error reopens.** Some drivers stop asking a rerouted stream for sound without reporting anything. `maintain()` now reopens an output whose clock stands still for two seconds while playing, and reports `Reason::Stalled`. Time the system spent asleep does not count. This replaces Spotifast's own watchdog by @dennisgr7 (spotifast#731). On a real device, 90 checks over seven seconds of playing, pausing and resuming reported no stall. By @crmne.
- **No crash when an audio device cannot be named.** A Bluetooth output that switched to another device could fail to describe itself, and the default-output watch then aborted the app. Such a device is now skipped until it can be named. By @aeries0x. (#22)
- **The fallback fonts are mapped, not read into memory.** Only the pages a glyph needs are loaded. On macOS the fonts went from 87 MB to 8.3 MB. On Linux with the usual Noto fonts, the process uses about 20 MiB less. By @darkhanakh (#17); thanks @natevick for the same change with the Linux measurements (#23).
- **A macOS title-bar double-click zooms when the setting says Zoom.** macOS stores Zoom as `Maximize`, which fastframe read as Fill. By @ZebulanStanphill. (#13)

## Known limitations

- **Not yet run on Windows or macOS hardware.** The power readers, the new macOS screen check and the Windows save routine pass CI on both platforms, but the test machines were not reachable for this release.
- **Platform gaps in `fastframe-power`.**
  - Battery, display, lock, metered networks and the end of the session are reported on Windows only.
  - Linux reports the saver profile, sleep and wake, but not the network.
  - macOS reports Low Power Mode and the network's reach, but not sleep or wake yet.

  The crate README has a table for each platform.
- **Hyprland does not raise yet.** Its `hyprctl dispatch` syntax changed in 0.56, so the same request fails on one version or the other.
