fastframe 0.5.1 lets the apps move their Windows installers from Inno Setup to MSI, since antivirus engines keep flagging Inno's `setup.exe`. A Windows installation now updates through the release's `.msi` when the release has one. Every new window also takes the zoom the app saved, and three smaller changes came out of moving Spotifast onto 0.5.0.

Upgrade by moving the tag on every fastframe crate:

```toml
fastframe-update = { git = "https://github.com/crmne/fastframe", tag = "v0.5.1" }
```

Nothing in an app has to change. To move to MSI, an app's Windows Installer package has to follow a few rules, and the app ships one bridge release. Both are under "Windows installs update through an MSI package" below.

## New

- **Windows installs update through an MSI package.** When a release has `<slug>-v<version>-<target>.msi`, the updater downloads it and checks it against the signed checksums, like any other download. The helper installs it silently with `msiexec`, into the folder the app runs from. Releases without a package still update through `-setup.exe`. Waiting for the app to quit, the backup, rollback and the relaunch work as before, and exit code 3010 (a restart is due) counts as installed. By @crmne.

  What the app's package must do:
  - install per user;
  - call its folder `INSTALLFOLDER`;
  - install the `<slug>-installer.txt` marker;
  - take over a copy its Inno setup program installed.

  An app moves in two releases. The first ships both the setup program and the package: older versions only know `-setup.exe` and update to it, and that release's updater picks the package from then on. Later releases can ship the package alone. The [fastframe-update README](https://github.com/crmne/fastframe/tree/v0.5.1/crates/fastframe-update#windows-installer-packages) has the details.
- **Every window takes the saved zoom (`fastframe_shell::window::keep_zoom`).** Without egui's saved memory, each new window starts at zoom 1, and Spotifast and ZapFast both reapplied their zoom by hand. `keep_zoom` applies the saved zoom when a window opens. After that it returns the zoom the user picks with Ctrl and plus or minus, for the app to save. A corrupt saved value is replaced by the nearest usable zoom. By @crmne.

## Fixed

- **A desktop portal that is slow to answer holds the app up for half a second, not a full one.** `fastframe_desktop::setting` now gives up sooner. By @crmne.
- **Clearer advice in the docs.**
  - `fastframe-power`'s `online` is a reason to wait, never to give up. Windows can report no internet behind a proxy the app gets through anyway.
  - `fastframe-file`'s saves are best made off the frame. The flush to the disk can take far longer than a frame on a busy or network drive.

  By @crmne.

## Known limitations

- **The MSI path has not been run on Windows hardware.** It passes CI on Windows, and its command line, exit codes and rollback have tests, but no app has shipped a package yet. The first bridge release is the real test.
