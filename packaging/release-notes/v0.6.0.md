fastframe 0.6.0 gives every app the title bar Spotifast draws itself, on macOS, Windows and Linux. It also fixes three things found on real Windows machines: installer updates that always failed for apps shipping DLLs, update folders piling up in the install folder, and apps reported as not responding while they sit in the tray.

Upgrade by moving the tag on every fastframe crate:

```toml
fastframe-titlebar = { git = "https://github.com/crmne/fastframe", tag = "v0.6.0" }
```

One change is required: **`fastframe-macos` is gone.** Its work is now part of `fastframe-titlebar`:

| Was | Now |
| --- | --- |
| `fastframe_macos::align_traffic_lights(frame, ctx, height)` | `fastframe_titlebar::align_traffic_lights(frame, ctx, height)` |
| `fastframe_macos::traffic_light_inset(ctx)` | `fastframe_titlebar::footprint(ctx, height).left` |
| `fastframe_macos::TRAFFIC_LIGHTS_WIDTH` | `fastframe_titlebar::TRAFFIC_LIGHTS_WIDTH` |
| `fastframe_macos::double_click_action()` in the app's own header drag | `fastframe_titlebar::drag(ui, rect)` |

[MIGRATION.md](https://github.com/crmne/fastframe/blob/v0.6.0/MIGRATION.md#fastframe-titlebar) lists what Spotifast, ZapFast and Solco each replace.

## New

- **The app's own title bar, on every platform (`fastframe-titlebar`).**
  - **macOS:** the header moves the window from the first press, as AppKit requires, and a double-click does what System Settings says (zoom, fill, minimize or nothing). The native traffic lights stay, centred in the header, with their room reserved.
  - **Windows and Linux:** when the user turns the platform's frame off, the app draws the caption buttons:
    - Windows' square ones, with the red Close;
    - or GNOME's round ones, in the desktop's button layout and with the icon theme's glyphs.

    Double-clicking the header maximizes the window, and the edges and corners resize it. `Footprint::reserve` puts the header's own controls beside the buttons, or under them when the window is narrow.

  It is Spotifast's title bar. ZapFast's macOS drag gains the double-click it lacked, and Solco's now starts on the press rather than once the pointer moves. By @crmne.

## Fixed

- **Installer updates work for apps that ship DLLs beside their executable.** The update helper is a copy of the app that runs from the update's staging folder. On Windows it found the app's DLLs only through its working directory, the install folder, so it held them while the installer had to replace them, and every installer update rolled back. Solco's update from 0.8.0-alpha.1 to 0.9.0-alpha.2 failed this way on Windows 11. The helper now carries its own copies of the DLLs and runs in the staging folder, and the relaunched app runs in its own folder. Copies installed before this release still have the old helper, so their users need to install the next version by hand once. Reported by the Solco session. By @crmne.
- **Update folders no longer pile up.** Each update left a `.<slug>-update-*` folder in the install folder, holding a copy of the app and its backup. Spotifast's held four, most of 300 MB, and they kept the uninstaller from removing the folder. Earlier updates' folders now go when the new version starts, and before each download. A folder whose helper is still working stays. The latest update's folder stays until the next update, so an uninstaller should remove `.<slug>-update-*` folders itself (on uninstall only, never during an update). Reported by the Spotifast session. By @crmne.
- **Apps in the tray no longer show as not responding on Windows.** winit keeps a small window on the main thread between windows. While the app waited in the tray, nothing answered that window's messages, so Windows marked the app as hung. Both the shell's own wait and `fastframe_tray::idle` now answer them. Diagnosed, with the patch, by the Spotifast session. By @crmne.

## Known limitations

- **The update fixes have not run end to end yet.** Their tests pass on a Windows 11 machine, but no app has shipped the fixed helper or the cleanup.
- **The macOS header behaviour has been compiled and tested on a Mac, not used by hand.** It is Spotifast's code, which has shipped.
- **Windows 11's snap layouts menu does not appear over the drawn Maximize button**, and Alt+Space does not open the window menu on the drawn header yet.
