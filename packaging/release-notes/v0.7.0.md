fastframe 0.7.0 keeps audio playing on a busy Mac: the thread that decodes and queues sound can now ask for precedence over ordinary work, as Solco's audition already does. It also brings two crates from ZapFast and Solco, native notifications and the Dock icon with its unread badge, and makes the macOS menu-bar item open its menu on every click.

Upgrade by moving every fastframe crate to the tag:

```toml
fastframe-audio = { git = "https://github.com/crmne/fastframe", tag = "v0.7.0" }
```

One change is required: **`fastframe_tray::Config::menu_on_click` is gone.** On macOS either click on the menu-bar item now opens its menu, as menu-bar items do; remove the field from your `Config`.

## New

- **The thread that feeds the audio output can take precedence (`fastframe_audio::raise_feeder_priority`).** The output's callback already runs on the audio system's own real-time thread, but the thread that decodes and queues what it plays ran like any other, so a busy or swapping Mac could keep it waiting until the queue ran dry: crackles and gaps of up to two seconds in Spotifast (crmne/spotifast#785). Call it once on that thread. It asks for the user-interactive QoS class on macOS, one step above normal priority on Windows, and nice -5 on Linux (usually refused without privileges, which is harmless). It is the policy Solco gives its audition decoder (Solco ADR 0190). Reported by @sriram3720. By @crmne.
- **Native notifications for GUI apps, TUIs and background agents (`fastframe-notifications`).** One `Client` delivers, updates and withdraws notifications on Linux, macOS and Windows, with click events, and separates checking permission from asking for it. Extracted from ZapFast's message notifications and Solco's task notifications. [MIGRATION.md](https://github.com/crmne/fastframe/blob/v0.7.0/MIGRATION.md#native-notifications) says what each app replaces. By @crmne.
- **The Dock icon and unread badge, independent of the windows (`fastframe-dock`).** `set_icon` gives an unbundled macOS run, such as `cargo run`, the app's icon instead of the generic executable one, and `Badge` shows an unread count on the macOS Dock, through the Unity Launcher API on Linux (Plasma and compatible launchers), and with `Taskbar` on the Windows taskbar. Extracted from ZapFast's badges. By @crmne.
- **`fastframe_desktop::macos_notifications_allowed`** checks ZapFast's way whether the real application bundle may notify, so unbundled development runs stay silent. By @crmne.

## Fixed

- **The macOS menu-bar item opens its menu on every click.** A left click used to toggle the window instead, unless the app opted in. By @crmne.
- **Clicking the Dock icon opens a window after a hidden start on macOS.** The Dock reopen handler is installed again once the first window attaches and winit's application delegate exists. Starting hidden also needs [rust-windowing/winit#4770](https://github.com/rust-windowing/winit/pull/4770), which the apps' winit fork carries. By @crmne.

## Known limitations

- **The feeder priority was measured on an M4 Mac mini under CPU load, not under the memory pressure in the report.** With 40 busy loops on 10 cores, the longest a 5 ms sleep of the feeding thread took went from 17 to 34 ms down to about 8 ms; the 200 ms queue did not run dry either way on that machine. Swapping can still stall any thread, whatever its priority.
