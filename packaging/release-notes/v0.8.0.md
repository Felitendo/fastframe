fastframe 0.8.0 brings the desktop features Spotifast users asked for, ready for every app: starting at login (in the tray if you like), keeping the computer awake while audio plays, a portable Windows copy that keeps its data beside it, AppImages that update themselves, a menu-bar-only mode on macOS, white or black tray icons, and a light and a dark palette that follow the system. It also fixes audio that never came back on Windows after a Bluetooth headset connected.

Upgrade by moving every fastframe crate to the tag:

```toml
fastframe-audio = { git = "https://github.com/crmne/fastframe", tag = "v0.8.0" }
```

No change is required. Two new crates arrive, `fastframe-autostart` and `fastframe-dirs`, and [MIGRATION.md](https://github.com/crmne/fastframe/blob/v0.8.0/MIGRATION.md) says what ZapFast and the Chat with Work local agent can delete in favour of `fastframe-autostart`. An app that turns on AppImage updates (`UpdateConfig::appimage`) must first list its AppImages in the signed `checksums.txt` and translate the new `Unsupported::NotWritable`.

## New

- **Start apps at login, with the window or in the tray (`fastframe-autostart`).** One `Autostart` registers the app and reads the registration back from the platform each time, so a change made in System Settings, Task Manager or the desktop shows in the app: an XDG autostart entry on Linux (the background portal inside Flatpak), a login item through `SMAppService` on macOS 13 and later (a bundled agent for starting hidden, since a login item cannot pass arguments), and the `Run` key on Windows. Shared with ZapFast's and the Chat with Work local agent's own autostart code. Asked for in crmne/spotifast#122 by @gabrieleancora. By @crmne.
- **Keep the computer awake while audio plays (`fastframe_power::KeepAwake`).** It blocks idle sleep only: the display still turns off, the screen still locks, and the user can still put the computer to sleep. macOS takes an `NSProcessInfo` activity, Windows a system power request, and Linux the desktop portal's Inhibit (inside Flatpak too) or a logind lock. `Power::keep_awake` hands out an inert hold from a fixed `Power`, so tests and demo runs never keep the real machine awake. Asked for in crmne/spotifast#962 by @marcinkurek. By @crmne.
- **A portable Windows copy keeps its data next to it (`fastframe-dirs`).** A copy unpacked from the `.zip`, beside its `<slug>-portable.txt`, keeps its config, state and cache in `<slug>-data` next to the executable. The first portable start copies, never moves, the per-user settings and state, so nothing is lost and an installed copy keeps its own. Installed copies, Linux and macOS keep their folders. `Portable::instance_scope` gives a portable copy its own single-instance slot. Asked for in crmne/spotifast#703 by @KuroZantetsuken. By @crmne.
- **An AppImage can update itself in place (`UpdateConfig::appimage`).** The release's AppImage is checked against the signed checksums like any other download, then renamed over the running one, with the usual rollback. Off by default, for apps whose AppImage is not signed yet. Asked for in crmne/spotifast#737 by @shuvashish76. By @crmne.
- **Apps can drop their macOS Dock icon while running (`fastframe_dock::set_dock_icon_visible`).** It turns the app into a menu-bar-only one and back again, with no restart, and keeps it in front. Asked for in crmne/spotifast#837 by @curlyhacker. By @crmne.
- **Tray icons can be white or black to match the panel (`Tray::set_icon_colour`).** White and Black paint the app's template shape, switching in place on every platform. Asked for in crmne/spotifast#128 by @joy4eg. By @crmne.
- **Follow system can pair a light and a dark palette (`fastframe_theme::Pair`).** It picks the palette to show as the system switches, lists the palettes each side can take, and falls back to the last colours read when a palette file goes away. Asked for in crmne/spotifast#619 by @santiruffino. By @crmne.

## Fixed

- **Audio comes back on Windows after a Bluetooth headset connects.** Since cpal 0.18 the default output was WASAPI's virtual default device, which stops activating for the rest of the process once its change notifications have run (RustAudio/cpal#1402), so every reopen failed with "Cannot change thread mode after it is set" until the app restarted. The output now opens the endpoint the default is at that moment, and follows the default itself as before. Reported in crmne/spotifast#689 by @TnZzZHlp. By @crmne.

## Known limitations

- **Most of this has run only in tests and CI.** No login item was registered on a real Mac, no Run key or portal request was made, no AppImage was replaced by a published release, and the Bluetooth fix was not tried on a Windows machine with a headset.
- **Keeping awake on Linux depends on the desktop.** GNOME and KDE honour the portal's request; a desktop whose portal ignores it keeps its own idle behaviour.
