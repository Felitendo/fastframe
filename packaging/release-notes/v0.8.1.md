fastframe 0.8.1 lets an app start in the tray at login on macOS. In 0.8.0, turning on "start hidden" for the first time always failed with "the bundle carries no launch agent to start hidden", even when the bundle carried it.

Upgrade by moving the tag on every fastframe crate; nothing else changes:

```toml
fastframe-autostart = { git = "https://github.com/crmne/fastframe", tag = "v0.8.1" }
```

## Fixed

- **Starting hidden at login works the first time on macOS (`fastframe-autostart`).** `SMAppService` reports an agent it has never registered as not found, the same status it gives a plist the bundle lacks, so 0.8.0 refused to register the agent at all. `Autostart` now looks for the agent's plist in the bundle's `Contents/Library/LaunchAgents` instead, and registers it when it is there. Seen on macOS 27.0.1 with Spotifast's bundle, where registering the agent succeeded and loaded the job. Reported in crmne/spotifast#122 by @gabrieleancora. By @crmne.
