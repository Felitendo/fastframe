fastframe 0.9.0 makes Windows notifications appear at all for an app without a packaged identity, and lets notifications show the app's logo on Windows and on Linux builds that have no installed icon.

Upgrade by moving every fastframe crate to the tag:

```toml
fastframe-notifications = { git = "https://github.com/crmne/fastframe", tag = "v0.9.0" }
```

No change is required. To show the logo, write it to a stable file and pass its absolute path to `App::icon_file`.

## New

- **Notifications can show the app's logo (`App::icon_file`).** On Windows it becomes the AppUserModelID's `IconUri`, so toasts show the logo instead of a blank icon. On Linux it is sent in place of the theme icon name when neither the `hicolor` theme nor `pixmaps` has that icon, as in a portable archive or a development build; installed packages keep following the theme. macOS keeps showing the bundle's icon. By @crmne.

## Fixed

- **Windows toasts show for an app with no Start menu AppUserModelID (`fastframe-notifications`).** `ToastNotifier.Setting` fails with `ERROR_NOT_FOUND` for an AppUserModelID registered only in the registry, which is how fastframe registers portable and MSI-installed apps. Every `show` turned that into `Error::Delivery`, so no toast ever appeared. It now reads as `Permission::NotDetermined`, and the toast is shown. Found on Windows 11 while testing Solco's notifications. By @crmne.

## Known limitations

- **Windows may invert a single-hue logo.** In the dark theme, Windows 11 drew Solco's dark violet logo with inverted colours in the toast header, with or without `IconBackgroundColor`, while a red and blue test icon kept its colours. Apps with a single-hue logo should look at their toasts.
