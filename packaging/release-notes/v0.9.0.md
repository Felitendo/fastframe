fastframe 0.9.0 makes Windows notifications appear at all for an app without a packaged identity, and shows the app's logo on them in its own colours, in the dark and the light theme. Linux builds without an installed icon show the logo too, and an app sitting in the tray no longer grows its memory tick after tick.

Upgrade by moving every fastframe crate to the tag:

```toml
fastframe-notifications = { git = "https://github.com/crmne/fastframe", tag = "v0.9.0" }
```

No change is required. To show the logo, pass a PNG of it and a saturated colour from the app's brand to `App::logo`.

## New

- **Notifications show the app's logo, in its own colours (`App::logo`).** Give it a PNG of the logo and a brand colour, and `Client::new` writes the file the desktop reads to the per-user cache. On Windows the toast shows the logo centred on an opaque square of that colour. Windows 11 inverts the colours of a toast icon it judges monochrome when the dark theme is on: on a Windows 11 25H2 machine, a one-hue mark on transparency and Solco's dark, mostly grey tile both came out inverted, with or without `IconBackgroundColor`, while every opaque icon framed in a saturated colour kept its colours in both themes. On Linux the PNG itself is sent in place of the theme icon name when neither the `hicolor` theme nor `pixmaps` has that icon, as in a portable archive or a development build; installed packages keep following the theme. macOS keeps showing the bundle's icon. By @crmne.

## Fixed

- **Windows toasts show for an app with no Start menu AppUserModelID (`fastframe-notifications`).** `ToastNotifier.Setting` fails with `ERROR_NOT_FOUND` for an AppUserModelID registered only in the registry, which is how fastframe registers portable and MSI-installed apps. Every `show` turned that into `Error::Delivery`, so no toast ever appeared. It now reads as `Permission::NotDetermined`, and the toast is shown. Found on Windows 11 while testing Solco's notifications. By @crmne.

- **An app sitting in the tray no longer grows its memory (`fastframe-shell`).** The shell gave the app one egui context while it ran without a window and never ran a pass on it, so every repaint the app asked for stayed for as long as it sat in the tray, about 76 bytes a tick in Spotifast. Each tick is now one egui pass, and what it asked for is let go when it ends. Reported in crmne/spotifast#954 by @kkatnaomi. By @crmne.

## Dependencies

- `fastframe-notifications` now uses `png` 0.18, already in the workspace through `fastframe-emoji` and in Solco's, ZapFast's and Spotifast's dependency trees, to read the logo and write the Windows tile, and `directories` 6, already used by `fastframe-dirs`, for the cache folder.

## Known limitations

- **The colour has to be a colour.** The tile keeps a logo's colours because of its band of saturated colour; a grey or black one can still be inverted.
- **Windows' rule is not documented.** The behaviour above was measured on one Windows 11 machine, build 26200, and a later Windows may judge icons differently.
